Slots represent scheduled publishing events — a piece of content lined up to go live on a specific platform account at a specific time. The Slots API lets you list everything in your schedule along with how much headroom remains in each platform lane's publishing cap, create new slots by specifying either a UTC timestamp or a local time with timezone, adjust timing, cancel slots before they fire, and publish a slot immediately without waiting for its scheduled time.

<Note>
  Your slot list is capped at **200 items**. The `GET /api/slots` response includes per-lane cap headroom so you can see how many more slots each platform lane can absorb before hitting its daily limit.
</Note>

---

## List slots

### `GET /api/slots`

Returns up to 200 slots across all your platform accounts ordered by scheduled time ascending, plus a `headroom` array showing remaining capacity per active lane.

<CodeGroup>
```bash cURL
curl -s https://air.wzrd.tech/api/slots \
  --cookie "session=<your-session-cookie>"
```

```typescript TypeScript
const res = await fetch('https://air.wzrd.tech/api/slots', {
  credentials: 'include',
});
const { slots, headroom } = await res.json();
```
</CodeGroup>

**Response** — `200 OK`

<ResponseField name="slots" type="array">
  Array of slot objects, up to 200, ordered by `scheduled_at` ascending.
</ResponseField>

<ResponseField name="slots[].id" type="string">
  Unique slot identifier.
</ResponseField>

<ResponseField name="slots[].platform" type="string">
  The target publishing platform. One of `"instagram"`, `"facebook"`, `"x"`, `"youtube"`, `"tiktok"`.
</ResponseField>

<ResponseField name="slots[].account_ref" type="string">
  Reference to the connected account to publish from.
</ResponseField>

<ResponseField name="slots[].package_ref" type="string">
  Reference to the content package or asset bundle to publish.
</ResponseField>

<ResponseField name="slots[].status" type="string">
  Current slot status. One of `"scheduled"`, `"proposed"`, `"parked"`, `"publishing"`, `"published"`, `"cancelled"`, `"failed"`.
</ResponseField>

<ResponseField name="slots[].scheduled_at" type="string">
  UTC ISO 8601 timestamp of the scheduled publish time.
</ResponseField>

<ResponseField name="slots[].timezone" type="string">
  IANA timezone identifier used when the slot was created, e.g. `"America/New_York"`.
</ResponseField>

<ResponseField name="headroom" type="array">
  Per-lane capacity headroom for each active platform + account combination.
</ResponseField>

<ResponseField name="headroom[].platform" type="string">
  The platform for this lane.
</ResponseField>

<ResponseField name="headroom[].account_ref" type="string">
  The account reference for this lane.
</ResponseField>

<ResponseField name="headroom[].allowed" type="boolean">
  `true` if a new slot in this lane could fire right now without hitting the daily cap.
</ResponseField>

<ResponseField name="headroom[].used" type="number">
  Number of publishes already consumed in the current 24-hour window for this lane.
</ResponseField>

<ResponseField name="headroom[].cap" type="number">
  The daily publish cap for this lane.
</ResponseField>

<ResponseField name="headroom[].nextWindow" type="string | null">
  ISO 8601 timestamp of when the oldest publish in the window ages out, freeing capacity. `null` if the cap has not been reached.
</ResponseField>

## Schedule a new slot

### `POST /api/slots`

Creates a new content slot. You can specify the publish time as a UTC ISO 8601 timestamp, or as a local time string paired with a timezone identifier — Airv converts local time to UTC for you. The `timezone` field is required regardless of which time format you use.

<ParamField body="platform" type="string" required>
  The target platform. Must be one of `"instagram"`, `"facebook"`, `"x"`, `"youtube"`, `"tiktok"`.
</ParamField>

<ParamField body="account_ref" type="string" required>
  The account reference identifying which connected account to post from.
</ParamField>

<ParamField body="package_ref" type="string" required>
  The content package or asset bundle reference to publish.
</ParamField>

<ParamField body="timezone" type="string" required>
  IANA timezone identifier, e.g. `"America/New_York"`, `"Europe/London"`. Required for all slots — used to handle DST transitions correctly.
</ParamField>

<ParamField body="scheduled_at" type="string">
  UTC ISO 8601 datetime string, e.g. `"2024-06-12T14:00:00Z"`. Use this **or** `local_time`, not both.
</ParamField>

<ParamField body="local_time" type="string">
  Local time in `YYYY-MM-DDTHH:mm:ss` format, e.g. `"2024-06-12T09:00:00"`. Airv converts this to UTC using the supplied `timezone`. Use this **or** `scheduled_at`, not both.
</ParamField>

<CodeGroup>
```bash cURL (UTC timestamp)
curl -s -X POST https://air.wzrd.tech/api/slots \
  -H "Content-Type: application/json" \
  --cookie "session=<your-session-cookie>" \
  -d '{
    "platform": "x",
    "account_ref": "acct_x01",
    "package_ref": "pkg_abc",
    "scheduled_at": "2024-06-12T14:00:00Z",
    "timezone": "America/New_York"
  }'
```

```bash cURL (local time)
curl -s -X POST https://air.wzrd.tech/api/slots \
  -H "Content-Type: application/json" \
  --cookie "session=<your-session-cookie>" \
  -d '{
    "platform": "instagram",
    "account_ref": "acct_ig01",
    "package_ref": "pkg_def",
    "local_time": "2024-06-12T09:00:00",
    "timezone": "America/New_York"
  }'
```

```typescript TypeScript (UTC timestamp)
const res = await fetch('https://air.wzrd.tech/api/slots', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    platform: 'x',
    account_ref: 'acct_x01',
    package_ref: 'pkg_abc',
    scheduled_at: '2024-06-12T14:00:00Z',
    timezone: 'America/New_York',
  }),
});
const { slot } = await res.json();
```

```typescript TypeScript (local time)
const res = await fetch('https://air.wzrd.tech/api/slots', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    platform: 'instagram',
    account_ref: 'acct_ig01',
    package_ref: 'pkg_def',
    local_time: '2024-06-12T09:00:00',
    timezone: 'America/New_York',
  }),
});
const { slot } = await res.json();
```
</CodeGroup>

**Response** — `201 Created`

<ResponseField name="slot" type="object">
  The newly created slot object.
</ResponseField>

```json
{
  "slot": {
    "id": "slt_003",
    "platform": "instagram",
    "account_ref": "acct_ig01",
    "package_ref": "pkg_def",
    "status": "scheduled",
    "scheduled_at": "2024-06-12T13:00:00Z",
    "timezone": "America/New_York"
  }
}
```

## Reschedule a slot

### `PATCH /api/slots/[id]`

Updates the scheduled publish time for an existing slot. You can pass either a UTC `scheduled_at` timestamp or a `local_time` + `timezone` pair. Only slots in `"scheduled"`, `"parked"`, or `"proposed"` status can be rescheduled. Slots with `"proposed"` status remain in `"proposed"` after rescheduling — rescheduling a proposal does not approve it.

<ParamField path="id" type="string" required>
  The slot ID to reschedule.
</ParamField>

<ParamField body="scheduled_at" type="string">
  New UTC ISO 8601 datetime string. Use this **or** `local_time` + `timezone`, not both.
</ParamField>

<ParamField body="local_time" type="string">
  New local time in `YYYY-MM-DDTHH:mm:ss` format. Must be paired with `timezone`.
</ParamField>

<ParamField body="timezone" type="string">
  IANA timezone identifier. Required when using `local_time`; also used to override the slot's stored timezone when provided with `scheduled_at`.
</ParamField>

<CodeGroup>
```bash cURL
curl -s -X PATCH https://air.wzrd.tech/api/slots/slt_001 \
  -H "Content-Type: application/json" \
  --cookie "session=<your-session-cookie>" \
  -d '{ "scheduled_at": "2024-06-13T16:00:00Z", "timezone": "America/New_York" }'
```

```typescript TypeScript
const res = await fetch('https://air.wzrd.tech/api/slots/slt_001', {
  method: 'PATCH',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ scheduled_at: '2024-06-13T16:00:00Z', timezone: 'America/New_York' }),
});
const { slot } = await res.json();
```
</CodeGroup>

**Response** — `200 OK`

<ResponseField name="slot" type="object">
  The updated slot object with the new `scheduled_at`, `timezone`, and `status`.
</ResponseField>

```json
{
  "slot": {
    "id": "slt_001",
    "scheduled_at": "2024-06-13T16:00:00Z",
    "timezone": "America/New_York",
    "status": "scheduled"
  }
}
```

<Note>
  Rescheduling a `"proposed"` slot does **not** promote it to `"scheduled"`. Its status stays `"proposed"` until you explicitly approve it through the decisions queue.
</Note>

## Cancel a slot

### `DELETE /api/slots/[id]`

Cancels a slot, preventing it from being published at its scheduled time. You can only cancel slots in `"scheduled"`, `"parked"`, or `"proposed"` status. Slots in any other status cannot be cancelled.

<ParamField path="id" type="string" required>
  The slot ID to cancel.
</ParamField>

<CodeGroup>
```bash cURL
curl -s -X DELETE https://air.wzrd.tech/api/slots/slt_001 \
  --cookie "session=<your-session-cookie>"
```

```typescript TypeScript
const res = await fetch('https://air.wzrd.tech/api/slots/slt_001', {
  method: 'DELETE',
  credentials: 'include',
});
const { ok } = await res.json();
```
</CodeGroup>

**Response** — `200 OK`

<ResponseField name="ok" type="boolean">
  `true` when the slot was successfully cancelled.
</ResponseField>

```json
{
  "ok": true
}
```

## Publish immediately

### `POST /api/slots/[id]/publish`

Publishes a slot right now, bypassing its scheduled time. Only slots in `"scheduled"` or `"parked"` status can be published immediately. If the publishing infrastructure is already warm, the response arrives synchronously with the outcome. If capacity is not available, the server returns `202 Accepted` with `outcome: "queued"` and the slot will be published automatically on the next sweep — you do not need to retry.

This operation has a maxDuration of 300 seconds.

<ParamField path="id" type="string" required>
  The slot ID to publish immediately.
</ParamField>

<CodeGroup>
```bash cURL
curl -s -X POST https://air.wzrd.tech/api/slots/slt_001/publish \
  --cookie "session=<your-session-cookie>"
```

```typescript TypeScript
const res = await fetch('https://air.wzrd.tech/api/slots/slt_001/publish', {
  method: 'POST',
  credentials: 'include',
});
const { outcome, slot } = await res.json();

if (res.status === 202) {
  // Slot is queued — publishing will happen automatically
  console.log('Publishing queued, outcome:', outcome);
} else {
  console.log('Published:', outcome, slot);
}
```
</CodeGroup>

**Response — synchronous** — `200 OK`

<ResponseField name="outcome" type="string">
  Result of the publish attempt, e.g. `"published"` or `"failed"`.
</ResponseField>

<ResponseField name="slot" type="object | null">
  The updated slot object reflecting the post-publish state.
</ResponseField>

```json
{
  "outcome": "published",
  "slot": {
    "id": "slt_001",
    "platform": "x",
    "account_ref": "acct_x01",
    "package_ref": "pkg_abc",
    "status": "published",
    "scheduled_at": "2024-06-12T14:00:00Z"
  }
}
```

**Response — queued** — `202 Accepted`

<ResponseField name="outcome" type="string">
  Always `"queued"` on a 202 response. The slot will be published automatically on the next scheduled sweep.
</ResponseField>

```json
{
  "outcome": "queued"
}
```

## Error cases

| Status | Meaning |
|--------|---------|
| `400` | Missing required fields, invalid `platform`, invalid `timezone`, or `scheduled_at` and `local_time` were supplied together. |
| `401` | Session cookie is missing or expired. |
| `404` | No slot with the given ID exists in your account. |
| `409` | The slot cannot be modified — it is not in an editable status (`DELETE`/`PATCH`), or it is not in `"scheduled"` or `"parked"` status (`publish`). |
| `502` | Publish attempt failed. Check the slot status and retry. |
| `500` | Internal error. |
