Airv authenticates every API request using an `airv_session` httpOnly cookie that is issued after you verify your phone number with a one-time passcode (OTP). In a browser the cookie is scoped to `air.wzrd.tech` and attached to all requests automatically. For server-side or programmatic use, capture the `Set-Cookie` value from the verify response and forward it in the `Cookie` header on subsequent calls.

## Session Cookie

The `airv_session` cookie is **httpOnly** and **scoped to `air.wzrd.tech`**. Because it is httpOnly, JavaScript cannot read the cookie value directly — the browser forwards it transparently on every same-origin request. When calling the API from a server or a non-browser environment, extract the cookie from the `Set-Cookie` response header after login and store it securely.

<Warning>
  Never log or expose the raw `airv_session` value. Treat it with the same care as a password or API secret key.
</Warning>

## Login Flow

The login flow is a two-step OTP exchange. New users who have not yet created an account go through an additional signup step after verification.

<Steps>
  <Step title="Request an OTP">
    Send your phone number to initiate an OTP delivery. Airv sends a one-time code to the number via SMS.

    ```http
    POST /api/auth/login
    Content-Type: application/json
    ```

    <ParamField body="phone" type="string" required>
      Your phone number in E.164 format (e.g., `+15551234567`).
    </ParamField>
  </Step>

  <Step title="Verify the OTP">
    Submit the code you received. On success, the server sets the `airv_session` cookie and returns your user object.

    If the phone number is not yet registered, the response returns a `signup_token` instead of user data — proceed to Step 3.

    ```http
    POST /api/auth/login
    Content-Type: application/json
    ```

    <ParamField body="phone" type="string" required>
      The same phone number you used in Step 1.
    </ParamField>

    <ParamField body="code" type="string" required>
      The 6-digit OTP delivered to your phone.
    </ParamField>
  </Step>

  <Step title="Sign up (new users only)">
    If Step 2 returned a `signup_token`, your phone number is not yet associated with an Airv account. Exchange the token to provision a new account and receive a session cookie.

    ```http
    POST /api/auth/signup
    Content-Type: application/json
    ```

    <ParamField body="signup_token" type="string" required>
      The short-lived token returned by the OTP verification step for unregistered numbers.
    </ParamField>
  </Step>
</Steps>

## Code Examples

The three code blocks below walk through the complete login flow in TypeScript using the browser `fetch` API. Pass `credentials: 'include'` so the browser stores and forwards the session cookie automatically.

<CodeGroup>

```typescript Step 1 — Request OTP
const res = await fetch('https://air.wzrd.tech/api/auth/login', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ phone: '+15551234567' }),
});

if (!res.ok) {
  const { error } = await res.json();
  throw new Error(`Failed to send OTP: ${error}`);
}

// OTP has been sent — prompt the user to enter the code
console.log('OTP sent successfully');
```

```typescript Step 2 — Verify OTP
const res = await fetch('https://air.wzrd.tech/api/auth/login', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    phone: '+15551234567',
    code: '123456',
  }),
});

const data = await res.json();

if (!res.ok) {
  throw new Error(`OTP verification failed: ${data.error}`);
}

if (data.signup_token) {
  // Phone is not yet registered — proceed to Step 3
  console.log('New user — signup required', data.signup_token);
} else {
  // Existing user — session cookie is now set
  console.log('Logged in as', data.user.username);
}
```

```typescript Step 3 — Sign Up (new users)
const res = await fetch('https://air.wzrd.tech/api/auth/signup', {
  method: 'POST',
  credentials: 'include',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ signup_token: '<signup_token_from_step_2>' }),
});

if (!res.ok) {
  const { error } = await res.json();
  throw new Error(`Signup failed: ${error}`);
}

const data = await res.json();
// Session cookie is now set — account provisioned
console.log('Account created for', data.user.username);
```

</CodeGroup>

## Server-Side Usage

When calling the API from a server (Node.js, edge functions, scripts), the browser does not manage cookies for you. Extract the `Set-Cookie` header from the login response and forward the cookie value on every subsequent request.

```typescript
import { parse } from 'cookie'; // npm install cookie

// After OTP verification...
const loginRes = await fetch('https://air.wzrd.tech/api/auth/login', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ phone: '+15551234567', code: '123456' }),
});

const rawCookie = loginRes.headers.get('set-cookie') ?? '';
const sessionCookie = rawCookie.split(';')[0]; // e.g. "airv_session=<value>"

// Use the extracted cookie on all subsequent requests
const meRes = await fetch('https://air.wzrd.tech/api/me', {
  headers: { Cookie: sessionCookie },
});

const profile = await meRes.json();
console.log(profile);
```

<Info>
  Store the session value in a secure, server-side secret store — never commit it to source control or include it in client-side bundles.
</Info>

## Logging Out

Send a `POST` to `/api/auth/logout` to invalidate the current session and clear the cookie. After this call, any request using the old cookie value returns `401`.

```http
POST /api/auth/logout
```

No request body is required. The server clears the `airv_session` cookie in the response.

## Session Expiry

Sessions expire after a period of inactivity. When your session expires, API requests return `401 Unauthorized`. Re-run the login flow (Steps 1–2 above) to obtain a fresh session.

<Tip>
  Before starting a long-running automated workflow, call `GET /api/me` to confirm your session is still valid. If you receive `401`, re-authenticate before proceeding.
</Tip>

## Error Responses

| Status | Meaning |
|--------|---------|
| `401 Unauthorized` | Your session cookie is missing, expired, or invalid. Re-authenticate. |
| `403 Forbidden` | Your session is valid but the requested action requires a higher permission tier. |

## Check Your Session — `GET /api/me` {#get-api-me}

Call `GET /api/me` at any time to confirm your session is active and to retrieve your full user profile. This endpoint is the canonical way to check authentication state in your application.

```typescript
const res = await fetch('https://air.wzrd.tech/api/me', {
  credentials: 'include', // sends session cookie automatically in browser
});

if (res.status === 401) {
  // Not authenticated — redirect to login
}

const user = await res.json();
console.log(user);
```

  Core identity information for the authenticated account.

  <Expandable title="user fields">

    </ResponseField>
    <ResponseField name="user.username" type="string">
      Your chosen display name on Airv.
    </ResponseField>
    <ResponseField name="user.wallet_address" type="string">
      The EVM wallet address associated with your account (provisioned via thirdweb).
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="entitlement" type="object">
  Your current plan capabilities and spend limits.

  <Expandable title="entitlement fields">
    <ResponseField name="entitlement.speed_tier" type="string">

    </ResponseField>
    <ResponseField name="entitlement.monthly_cap_usd" type="number">

    </ResponseField>
  </Expandable>
